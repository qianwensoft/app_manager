# Agent 问题反馈 - 扫码快速提交智能确认优化

**完成日期**: 2026-06-30  
**功能**: 优化快速提交功能，仅在内容改变时弹确认对话框，保留标题和描述

---

## 🎯 优化目标

解决快速提交功能的两个问题：
1. ✅ **描述字段正确保留** - 确保问题描述在快速提交时被正确读取和保存
2. ✅ **智能确认机制** - 仅在标题或描述改变时弹确认对话框，内容不变则直接提交

---

## 🔧 核心改进

### 1. 添加状态记录字段

```kotlin
// 快速提交：记录上次确认的标题和描述，避免重复确认
private var lastConfirmedTitle = ""
private var lastConfirmedDesc = ""
```

### 2. 智能确认逻辑

```kotlin
private fun quickSubmitWithBusinessNo() {
    val title = etTitle.text?.toString()?.trim() ?: ""
    val desc = etDesc.text?.toString()?.trim() ?: ""

    if (title.isEmpty()) {
        Toast.makeText(this, "请先填写标题", Toast.LENGTH_SHORT).show()
        return
    }

    // 检查标题和描述是否与上次确认的相同
    if (title == lastConfirmedTitle && desc == lastConfirmedDesc) {
        // 内容未变，直接提交，不弹确认对话框
        submitQuick()
    } else {
        // 内容改变，显示确认对话框
        AlertDialog.Builder(this)
            .setTitle("确认提交")
            .setMessage("业务单号: ${etBusinessNo.text}\n标题: $title\n描述: ${if (desc.isEmpty()) "（无）" else desc}\n\n确定立即提交反馈？")
            .setPositiveButton("提交") { _, _ ->
                // 记录本次确认的内容
                lastConfirmedTitle = title
                lastConfirmedDesc = desc
                submitQuick()
            }
            .setNegativeButton("取消", null)
            .show()
    }
}
```

### 3. 新增 submitQuick() 方法

与原 `submit()` 方法类似，但在提交成功后：
- **保留**：标题、描述
- **清空**：业务单号、其他编码、附件

```kotlin
private fun submitQuick() {
    // ... 提交逻辑（与 submit() 相同）...
    
    runOnUiThread {
        dialog.dismiss()
        Toast.makeText(this, "提交成功", Toast.LENGTH_SHORT).show()
        attachments.clear(); renderAttachments()
        // 快速提交模式：仅清空业务单号和其他编码，保留标题和描述
        etBusinessNo.setText(""); etOtherCodes.setText("")
    }
}
```

## 🔄 完整状态转换

### 状态1：未确认（初始状态）

```
lastConfirmedTitle = ""
lastConfirmedDesc = ""
```

**首次扫码**：
- 检查：title != lastConfirmedTitle（非空 != 空）
- 行为：弹出确认对话框
- 确认后：更新 lastConfirmedTitle 和 lastConfirmedDesc

### 状态2：已确认（内容不变）

```
lastConfirmedTitle = "设备无法启动"
lastConfirmedDesc = "按开机键无反应"
```

**再次扫码（内容不变）**：
- 检查：title == lastConfirmedTitle && desc == lastConfirmedDesc
- 行为：直接调用 submitQuick()，不弹对话框
- 确认后：不更新（内容未变）

### 状态3：内容改变

```
lastConfirmedTitle = "设备无法启动"
lastConfirmedDesc = "按开机键无反应"

用户修改：
title = "设备无法启动"
desc = "按开机键无反应，有异响"  ← 改变
```

**扫码（内容改变）**：
- 检查：desc != lastConfirmedDesc（"按开机键无反应，有异响" != "按开机键无反应"）
- 行为：弹出确认对话框（显示新的描述）
- 确认后：更新 lastConfirmedDesc = "按开机键无反应，有异响"

## 💡 设计考虑

### 为什么不使用"记住选择"复选框？

传统做法可能是在确认对话框中加一个"不再提示"复选框，但这种方式有问题：

❌ **问题1**：用户可能忘记自己曾经勾选过
❌ **问题2**：当用户修改标题/描述后，仍然不会弹窗，可能提交错误内容
❌ **问题3**：需要额外的设置入口来重置"不再提示"

### 当前方案的优势

✅ **智能检测**：自动检测内容是否改变，无需手动控制
✅ **无隐藏状态**：没有"不再提示"这种隐藏的全局状态
✅ **零学习成本**：用户不需要理解"记住选择"的含义
✅ **防止误操作**：内容改变时自动弹窗，防止提交错误信息
