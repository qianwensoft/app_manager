# 工作流引擎 Demo 快速测试指南

## 已创建的 Demo 工作流

当前系统中已创建了 **4 个 Demo 工作流**，可通过前端界面测试：

| ID | 编码 | 名称 | 类别 | 功能演示 |
|----|------|------|------|----------|
| 27 | `demo_async_tasks` | Demo: 异步任务 | 后台任务 | 异步执行、并发控制 |
| 28 | `demo_simple_test` | Demo: 简单测试 | 测试 | 基础HTTP调用 |
| 29 | `demo_api_retry` | Demo: API调用重试 | 外部集成 | 重试机制、指数退避 |

## 🎯 前端测试步骤（推荐）

### 方法一：通过数据接口页面执行

1. **打开数据接口管理页面**
   ```
   http://localhost:3001/data
   ```

2. **找到 Demo 工作流**
   - 在接口列表中搜索 "Demo"
   - 或按类别筛选：后台任务、外部集成、定时任务

3. **执行工作流**
   - 点击工作流右侧的「调试」按钮
   - 在弹出的对话框中输入参数（大多数 Demo 不需要参数，输入 `{}` 即可）
   - 点击「执行」

4. **查看结果**
   - 执行完成后会显示结果
   - 包括执行状态、耗时、返回数据等

### 方法二：通过工作流执行日志查看

1. **打开执行日志页面**
   ```
   http://localhost:3001/workflow-logs
   ```

2. **查看执行记录**
   - 最新的执行记录会显示在列表顶部
   - 可以按接口编码筛选（如：`demo_async_tasks`）

3. **查看详细信息**
   - 点击「详情」查看完整的步骤执行日志
   - 点击「时间线」查看可视化执行流程
   - 失败的记录可以点击「重试」重新执行

### 方法三：通过工作流设计器查看

1. **打开工作流设计器**
   ```
   http://localhost:3001/workflow-designer
   ```

2. **导入现有工作流**
   - 从数据库查询工作流的 `workflow_json` 字段
   - 粘贴到设计器的 JSON 导入功能
   - 查看工作流的可视化结构

3. **编辑和测试**
   - 可以修改步骤配置
   - 添加新的步骤
   - 导出 JSON 后保存到数据接口

## 📋 各 Demo 测试说明

### Demo 1: 异步任务 (ID: 27)

**功能**: 演示异步任务并发执行

**测试步骤**:
1. 在数据接口页面找到 `demo_async_tasks`
2. 点击「调试」，输入参数 `{}`
3. 点击「执行」
4. **立即**打开异步任务监控页面：http://localhost:3001/async-tasks
5. 开启「自动刷新」查看运行中的异步任务

**预期结果**:
- 主流程快速返回（< 1秒）
- 异步任务监控页面显示 3 个后台任务（发送邮件、发送短信、记录日志）
- 任务状态从「运行中」变为「已完成」
- 总耗时约 2-3 秒（异步任务在后台执行）

### Demo 2: 简单测试 (ID: 28)

**功能**: 基础 HTTP 调用测试

**测试步骤**:
1. 找到 `demo_simple_test` 工作流
2. 点击「调试」，输入 `{}`
3. 点击「执行」

**预期结果**:
- 调用 httpbin.org/get 成功
- 返回 HTTP 响应数据
- 耗时约 1-2 秒

### Demo 3: API调用重试 (ID: 29)

**功能**: 演示 HTTP 重试机制和指数退避

**测试步骤**:
1. 找到 `demo_api_retry` 工作流
2. 点击「调试」，输入 `{}`
3. 点击「执行」
4. 打开执行日志页面查看详细步骤

**预期结果**:
- 调用 httpbin.org/delay/1 成功（延迟1秒返回）
- 如果网络超时会自动重试（最多3次）
- 使用指数退避策略（500ms, 1s, 2s）
- 耗时约 1-2 秒（正常情况）

**触发重试测试**:
- 如果想看到重试效果，需要修改工作流配置
- 将 `timeout` 改为 500（比延迟时间短）
- 这样会触发超时重试

### Demo 4: 延迟执行 (ID: 30)

**功能**: 演示延迟步骤和时间控制

**测试步骤**:
1. 找到 `demo_delay` 工作流
2. 点击「调试」，输入 `{}`
3. 点击「执行」
4. **注意观察**执行进度和耗时

**预期结果**:
- 开始执行后等待 3 秒
- 总耗时约 3-4 秒
- 执行日志显示步骤2（等待3秒）耗时约3000ms

## 🗄️ 数据库查询验证

如果前端界面有问题，可以直接查询数据库验证：

```bash
# 查看执行记录
sqlite3 data/app-manager.db "
SELECT 
  request_id,
  interface_code,
  status,
  elapsed_ms,
  datetime(created_at, 'localtime') as created_at
FROM workflow_executions
ORDER BY created_at DESC
LIMIT 5;
"

# 查看步骤日志
sqlite3 data/app-manager.db "
SELECT 
  we.interface_code,
  wsl.step_id,
  wsl.status,
  wsl.elapsed_ms,
  wsl.retry_count
FROM workflow_executions we
JOIN workflow_step_logs wsl ON we.request_id = wsl.request_id
WHERE we.interface_code LIKE 'demo_%'
ORDER BY we.created_at DESC, wsl.step_order
LIMIT 10;
"
```
