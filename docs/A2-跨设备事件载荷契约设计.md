## 一、问题：三层传输的语义差

事件系统现有三种触达范围，语义**根本不同**：

| 范围 | 传输 | 同步性 | 上下文 | 现状 |
|---|---|---|---|---|
| 同 SPA 跨页面 | 内存 `eventManager` | 同步、可靠 | 共享（同一 AppState/PageState） | ✅ 已实现 |
| 同设备跨 form-app | AndroidBridge（WebView 间） | 准同步 | **不共享**（两个 SPA 实例） | ❌ 未做 |
| 跨设备 | 服务端 `/ws/stomp` 中继 | **异步、可丢、可重、有延迟** | **完全隔离**（两台设备） | ❌ 未做 |

**致命点**：现有动作链假设"触发与上下文在同一处"。动作里 `set_field`/`result_map` 回填、`$form.x`/`$node.x` 取值，全依赖**本地**的 PageState/nodeOutputs。设备 A emit 一个事件到设备 B，B 的动作链里 `$form.x` 指**谁的**表单？A 的（需随事件序列化携带）还是 B 的当前页？答案不定义清楚，跨设备动作就是空指针。

---

## 二、核心原则：跨设备事件只能携带「数据」，不能携带「上下文引用」

**跨设备事件 = 一个自包含的数据快照 + 一个事件名。** 它不携带、也不能依赖任何"对端运行时引用"。

```typescript
/** 跨设备事件信封（序列化后经 STOMP/Bridge 传输） */
export interface CrossDeviceEvent {
  /** 事件名（对端以 custom_event 源监听此名） */
  event: string
  /** 自包含数据快照（纯 JSON，对端经 $event.x 读取） */
  payload: Record<string, any>
  /** 来源标识（诊断 + 防回环，非寻址依赖） */
  origin: {
    formCode: string      // 来源 form-app
    deviceId?: string     // 来源设备（agent 注册 id）
    emittedAt: number     // 毫秒时间戳
    eventId: string       // 幂等去重键（uuid）
  }
  /** 跨设备跳数（防风暴，沿用 EmitScope.depth 思想） */
  hop: number
}
```

对端收到后，构造的 `EventContext`：
- `ctx.event = payload`（✅ 唯一可信数据源）
- `ctx.scan = undefined`，`ctx.form = 对端当前页快照`，`ctx.app = 对端 AppState`，`ctx.nodeOutputs = undefined`

**即：跨设备事件触发的动作链，`$event.x` 是携带来的数据；`$form/$app` 是对端本地状态（不是来源端的）。** 这必须在设计器明确提示。

## 三、动作白名单：跨设备触发时哪些动作可用

逐动作定边界（与 A3 的 current≠target 守卫一脉相承）：

| 动作 | 跨设备触发时 | 理由 |
|---|---|---|
| `toast` / `speak` | ✅ 允许 | 纯展示，无上下文依赖（值取 `$event.x` 或字面量） |
| `navigate` | ✅ 允许 | 切对端页面，本职 |
| `set_field scope=app` / 写 `$app` | ✅ 允许 | 写对端 AppState，自包含 |
| `emit_event`（本地再触发） | ✅ 允许（受 hop 守卫） | 对端本地事件链 |
| `call_interface`（不回填或回填 $app） | ✅ 允许 | 纯副作用 / 写自包含状态 |
| `set_field scope=page` / `result_map` 回填 page | ⚠️ **仅当对端有活动页**，否则 no-op + warn | 复用 A3 活动页代理守卫 |
| 取值用 `$form.x` / `$node.x` | ⚠️ 解析的是**对端**本地值（非来源端） | 设计器须提示；跨设备传值一律走 `$event.x` |

**硬规则**：跨设备事件的动作，**取值来源只应用 `$event.x` 和字面量**；用 `$form/$app/$node` 会取到对端本地状态，几乎总是 bug。设计器对"跨设备事件流"的值来源下拉应**默认只列 `$event.`**，其余给醒目警告。

## 四、寻址与权限（待决 #2 的答案）

### 4.1 寻址：topic 命名

复用现有 STOMP 约定（`/topic/<domain>/<id>/<sub>`，见 scada/device）：

```
/topic/form-app/<formCode>/events        # 广播给所有订阅该 form-app 的运行时
/topic/form-app/device/<deviceId>/events  # 定向给某设备（点对点）
```

- 运行时挂载时 `SUBSCRIBE` 自己 formCode（和/或 deviceId）的 topic。
- emit 跨设备事件 → 服务端 `PublishJSON(topic, CrossDeviceEvent)`。
- 集群已有 Redis 中继（`cluster.go` 的 `PublishJSONLocal` + 跨节点转发），**多节点天然覆盖**，无需额外改造。

### 4.2 权限：谁能 emit 到谁

跨 form-app emit **必须经服务端校验**（前端不可信）：

- 新增开放/内部端点 `POST /api/form-app/cross-event`（走 `AuthMiddleware`），body = `{target_form_code, event, payload}`。
- 服务端校验：调用方是否有权向 `target_form_code` 发事件。**默认拒绝跨 form-app**，需显式配置允许对（`global_config.cross_event_allow: [formCode...]`）。同 form-app 跨设备默认允许。
- 校验通过 → 服务端补全 `origin` + `eventId` → `PublishJSON`。
- **不允许前端直接 STOMP SEND 到 topic**（STOMP 只用于**订阅/接收**；发送一律走 HTTP 端点过权限）。

## 五、可靠性：异步传输的幂等/去重/防风暴

STOMP 是 at-most-once 且可能重投，必须在应用层兜：

- **幂等去重**：对端维护近期 `eventId` LRU（如 256 条），重复 `eventId` 直接丢弃。
- **防回环**：`origin.deviceId === 本机` 的事件丢弃（自己发的不自己收）。
- **防风暴**：`hop` 跨设备跳数上限（默认 3）；跨设备 emit 复用 `makeGuardedEmit` 的 scope 思想，`hop` 计入。超限丢弃 + 诊断日志。
- **不保证送达**：跨设备事件语义是"尽力广播"，**不能用于强一致流程**（如跨设备事务）。设计器须标注"跨设备事件不保证送达/不保证顺序"。

## 六、与协同（第 8 步 yjs）的衔接

- 本契约解决"**事件**跨设备"(一次性触发)。yjs 解决"**状态**跨设备"(持续同步的共享文档)。两者正交。
- AppState 若要跨设备**共享**(而非一次性 emit)，是 yjs 的活：把某 form-app 的 AppState 作为 yjs 文档，STOMP 作 provider transport。本契约的 `set_field scope=app` 跨设备只是"通知对端写自己的 AppState"，**不是共享同一份**。两者别混。
