# 工单外发配置占位符增强 - 快速验证指南

## 前置条件

1. 启动后端服务：`./bin/app-manager config.yaml`
2. 启动前端开发服务器：`cd web && npm run dev`
3. 登录系统并创建至少一个工单类型
4. 创建至少一个工单标签（在「工单管理」->「标签管理」）

## 验证步骤

### 1. 查看新增占位符

1. 进入「工单管理」->「外发配置」
2. 点击「新增 Webhook」
3. 在「入参映射」部分，点击「查看所有占位符」按钮
4. ✅ 验证在「基础信息」分类中可以看到：
   - `工单状态（编码）` - `{{status}}`
   - `工单状态（名称）` - `{{status_name}}`
   - `优先级（编码）` - `{{priority}}`
   - `优先级（名称）` - `{{priority_name}}`
   - `工单标签（编码）` - `{{tags}}`
   - `工单标签（名称）` - `{{tags_names}}`

### 2. 使用下拉框选择占位符

1. 在「入参映射」表格模式中，点击「+ 添加映射」
2. 在「值」列的下拉框中，展开「基础信息」分组
3. ✅ 验证可以看到新增的名称占位符选项
4. ✅ 验证选项格式为：`状态名称  {{status_name}}`

### 3. 测试多参数拼接示例

1. 在「值」列的下拉框中，展开「多参数拼接示例」分组
2. ✅ 验证可以看到以下新增示例：
   - `工单状态描述` - `工单{{code}}状态：{{status_name}}`
   - `工单优先级标题` - `【{{priority_name}}】{{title}}`

### 4. 复制占位符功能

1. 在占位符帮助对话框中，切换到「常用示例」标签页
2. ✅ 验证可以看到新增示例：
   - 工单状态描述：`工单 {{code}} 状态已更新为：{{status_name}}`
   - 工单标签列表：`标签：{{tags_names}}`
3. 点击任意示例的「复制」按钮
4. ✅ 验证提示「已复制到剪贴板」

### 5. 创建测试 Webhook 配置

**方案A：使用连接器接口（推荐）**

1. 先创建一个测试用的开放接口：
   - 进入「连接器管理」->「开放接口」
   - 创建接口，interface_code 为 `test_webhook`
   - 输入参数定义（可选）：
     ```json
     {
       "type": "object",
       "properties": {
         "order_code": {"type": "string"},
         "status_display": {"type": "string"},
         "priority_display": {"type": "string"},
         "tags_display": {"type": "string"}
       }
     }
     ```

2. 创建 Webhook 配置：
   - 名称：测试占位符
   - 目标类型：连接器接口
   - 连接器接口：选择 `test_webhook`
   - 入参映射（表格模式）：
     - `order_code` = `{{code}}`
     - `status_display` = `{{status_name}}`
     - `priority_display` = `{{priority_name}}`
     - `tags_display` = `{{tags_names}}`
   - 启用：是

**方案B：使用第三方接口**

1. 进入「出站管理」->「第三方接口」
2. 创建测试接口（可以用 webhook.site 或 requestbin.com 获取测试 URL）
3. 创建 Webhook 配置，目标选择该接口
4. 配置入参映射（同上）

### 6. 触发工单事件并验证

1. 创建一个新工单：
   - 标题：测试工单占位符
   - 优先级：紧急
   - 添加标签（需要先在标签管理中创建）：例如 `urgent`（紧急）、`hardware`（硬件故障）

2. 查看外发日志：
   - 进入「工单管理」->「外发日志」
   - 找到最新的外发记录
   - 点击查看详情
   - ✅ 验证请求体中的值：
     - `status_display` 应该是 `"待处理"` 而不是 `"open"`
     - `priority_display` 应该是 `"紧急"` 而不是 `"urgent"`
     - `tags_display` 应该是 `"紧急,硬件故障"` 而不是 `"urgent,hardware"`

3. 更新工单状态：
   - 将工单状态改为「处理中」
   - 再次查看外发日志
   - ✅ 验证 `status_display` 变为 `"处理中"`

### 7. 验证边界情况

**测试未知标签编码**
1. 直接通过 API 或数据库添加一个不存在的标签编码到工单
2. 触发工单事件
3. ✅ 验证 `tags_names` 中包含该未知编码（而不是报错或返回空）

**测试空标签**
1. 创建一个没有标签的工单
2. ✅ 验证 `tags_names` 为空字符串

**测试多个标签**
1. 创建一个有3个以上标签的工单
2. ✅ 验证 `tags_names` 正确用逗号分隔所有标签名称

## 常见问题

### Q1: 下拉框中没有看到新增的占位符
**A:** 刷新浏览器缓存（Ctrl+F5 或 Cmd+Shift+R），或清除浏览器缓存后重试

### Q2: 外发日志中显示的还是编码而非名称
**A:** 
- 检查 Webhook 配置的入参映射是否使用了 `_name` 后缀的占位符
- 确认后端服务已重启并加载了新代码
- 查看服务器日志是否有错误

### Q3: 标签名称没有显示
**A:** 
- 确认标签已在「标签管理」中创建
- 确认标签的 `code` 和工单关联的标签编码一致
- 检查数据库中 `work_order_tags` 和 `work_order_tag_links` 表

### Q4: 单元测试失败
**A:** 
```bash
cd server
go test ./api -run "TestWorkOrderStatusName|TestWorkOrderPriorityName" -v
```
如果失败，检查 `workOrderStatusName` 和 `workOrderPriorityName` 函数的映射表是否正确

## 性能验证

对于高并发场景，验证以下指标：

1. **标签查询性能**：
   - 单次查询耗时应 < 10ms（批量查询，非 N+1）
   - 可通过日志或 profiling 验证

2. **内存开销**：
   - 状态和优先级映射为内存常量，无额外开销
   - 标签名称查询会有少量临时对象分配

3. **并发测试**：
   - 同时创建100个工单，观察外发是否正常
   - 查看数据库连接池是否够用
