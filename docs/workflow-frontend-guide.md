# 工作流引擎前端使用指南

## 功能概述

工作流引擎提供了两个主要的前端界面：

1. **工作流设计器** - 可视化设计工作流
2. **工作流执行日志** - 查看和监控工作流执行情况

## 1. 工作流设计器

### 访问路径
菜单：**工作流设计器** 或 访问 `/workflow-designer`

### 功能特性

#### 1.1 可视化设计
- **拖拽式操作**：从左侧步骤面板拖拽步骤类型到画布
- **实时预览**：画布中央实时显示工作流结构
- **属性编辑**：右侧面板编辑选中步骤的详细配置

#### 1.2 支持的步骤类型

| 类型 | 名称 | 说明 |
|------|------|------|
| `sql` | SQL 查询 | 执行数据库操作 |
| `http` | HTTP 请求 | 调用外部 API |
| `script` | 脚本执行 | 运行 JavaScript 代码 |
| `interface` | 接口调用 | 调用其他数据接口 |
| `delay` | 延迟 | 等待指定时间 |
| `condition` | 条件分支 | 根据条件执行不同步骤 |

#### 1.3 高级配置

**异步执行**
- 开启后步骤在后台执行，不阻塞后续步骤
- 适用于通知、日志记录等不影响主流程的操作

**重试机制**
- 最大重试次数：1-10 次
- 退避策略：
  - 固定间隔
  - 线性增长
  - 指数退避
  - 自定义序列
- 重试条件：超时、网络错误、服务器错误

**事务管理**
- 为 SQL 步骤指定事务组
- 同一事务组内的步骤要么全部成功，要么全部回滚

#### 1.4 工作流操作

**查看 JSON**
- 点击"查看JSON"查看完整的工作流定义
- 支持手动编辑 JSON 后导入

**验证工作流**
- 点击"验证"检查工作流配置是否正确
- 自动检测缺失的必填字段

**测试运行**
- 点击"测试运行"模拟执行工作流
- 输入测试参数查看执行结果

**保存工作流**
- 点击"保存"将工作流保存到数据接口
- 需要在数据接口配置中指定

### 1.5 使用示例

**创建简单的订单处理流程**：

1. 从左侧拖拽"SQL 查询"到画布
   - 步骤ID：`create_order`
   - 数据源：`mysql_main`
   - SQL：`INSERT INTO orders (user_id, amount) VALUES (:request.user_id, :request.amount)`
   - 输出：`{"order_id": "{{last_insert_id}}"}`

2. 拖拽"HTTP 请求"到画布
   - 步骤ID：`send_notification`
   - 方法：POST
   - URL：`https://notify.example.com/send`
   - 开启"异步执行"
   - 开启"重试"，最大重试 3 次

3. 点击"查看JSON"复制完整配置

4. 在数据接口编辑页面：
   - 类型选择：`workflow`
   - 粘贴工作流 JSON 到 `workflow_json` 字段
   - 配置数据源映射到 `datasources_json`

## 2. 工作流执行日志

### 访问路径
菜单：**工作流执行日志** 或 访问 `/workflow-logs`

### 功能特性

#### 2.1 统计面板
页面顶部显示实时统计：
- **总执行次数** - 所有工作流执行的总次数
- **成功率** - 成功执行的百分比
- **平均时长** - 平均执行耗时（毫秒）
- **补偿次数** - 触发补偿机制的次数

#### 2.2 执行日志列表

**列表字段**：
- 请求ID - 唯一标识
- 接口编码 - 工作流所属的数据接口
- 状态 - 成功/失败/已补偿
- 步骤进度 - 完成步骤数 / 总步骤数（进度条）
- 耗时 - 执行时长（毫秒）
- 补偿 - 是否触发了补偿
- 创建时间

**状态标识**：
- 🟢 绿色：成功
- 🔴 红色：失败
- 🟡 黄色：已补偿

#### 2.3 筛选和搜索

**接口编码筛选**
- 输入接口编码过滤特定工作流的执行记录

**状态筛选**
- 成功 - 只显示成功的执行
- 失败 - 只显示失败的执行
- 补偿 - 只显示触发补偿的执行

**点击"统计"**
- 重新加载统计数据
- 应用当前筛选条件

#### 2.4 执行详情

点击列表行或"详情"按钮查看完整信息：

**基本信息**：
- 请求ID、接口编码
- 状态、是否补偿
- 总步骤数、完成步骤数
- 执行时长、补偿时长
- 创建时间

**步骤日志表格**：
- 显示每个步骤的执行情况
- 包含步骤ID、类型、状态
- 显示耗时和重试次数
- 失败步骤显示错误信息

#### 2.5 时间线视图

点击"时间线"按钮查看步骤执行的时间顺序：

- 📊 时间轴展示
- 每个步骤显示为卡片
- 包含详细的执行信息：
  - 步骤类型和标签
  - 执行时长
  - 重试次数
  - SQL 语句（如果是 SQL 步骤）
  - 输出结果（可折叠查看）
  - 错误信息（如果失败）

#### 2.6 重试执行

对于失败或补偿的执行，点击"重试"按钮：
- ⚠️ 注意：重试需要提供原始参数
- 建议直接重新调用工作流接口

### 2.7 分页

- 默认每页显示 20 条
- 支持 20/50/100 每页
- 总数显示

## 3. 与数据接口集成

### 3.1 在数据接口中配置工作流

1. 进入"数据源与接口"页面
2. 点击"数据接口"标签
3. 创建或编辑数据接口
4. 类型选择：`workflow`
5. 填写两个 JSON 配置：

**workflow_json**（工作流定义）：
```json
{
  "version": "1.0",
  "description": "订单处理流程",
  "steps": [
    {
      "id": "create_order",
      "type": "sql",
      "label": "创建订单",
      "datasource": "mysql_main",
      "sql": "INSERT INTO orders ...",
      "output": {
        "order_id": "{{last_insert_id}}"
      }
    }
  ]
}
```

**datasources_json**（数据源映射）：
```json
{
  "mysql_main": {
    "data_source_id": 1
  }
}
```

### 3.2 调用工作流接口

**开放接口调用**：
```bash
POST /api/open/v1/exec/{interface_code}
Content-Type: application/json
X-API-Key: your-api-key

{
  "user_id": 123,
  "amount": 100
}
```

**响应示例**：
```json
{
  "ok": true,
  "data": {
    "request_id": "wf_20260702_abc123",
    "status": "success",
    "total_steps": 3,
    "completed_steps": 3,
    "elapsed_ms": 245,
    "final_output": {
      "order_id": 12345
    }
  }
}
```

## 4. 最佳实践

### 4.1 设计工作流

✅ **推荐**：
- 给步骤起有意义的 ID 和标签
- 为耗时的 HTTP 请求配置重试
- 通知类操作使用异步执行
- 关键数据库操作放在事务组内

❌ **避免**：
- 异步步骤不要在事务组内
- 避免循环依赖
- 不要在异步步骤后使用其输出

### 4.2 监控和调试

1. **定期查看统计**
   - 关注成功率变化
   - 识别性能瓶颈（平均时长）

2. **失败日志分析**
   - 筛选失败的执行
   - 查看步骤日志找出问题步骤
   - 检查错误信息

3. **时间线视图**
   - 了解步骤执行顺序
   - 发现性能问题（某步骤耗时过长）

### 4.3 性能优化

- 合理使用异步执行减少总耗时
- 为频繁超时的步骤配置重试
- 避免在循环中执行重操作
- 优化 SQL 查询性能

## 5. 常见问题

### Q1: 工作流设计器中无法保存？
A: 设计器目前用于可视化设计和生成 JSON。完成设计后：
1. 点击"查看JSON"
2. 复制完整的 JSON
3. 在"数据源与接口"页面创建或编辑数据接口
4. 粘贴到 `workflow_json` 字段

### Q2: 异步步骤的执行结果在哪里查看？
A: 异步步骤不会阻塞主流程，查看方式：
1. 进入"工作流执行日志"
2. 找到对应的执行记录
3. 查看"步骤日志"，异步步骤会标记为"异步"
4. 或通过 API 查询：`GET /api/data-stack/async-tasks/:request_id/:step_id`

### Q3: 如何知道工作流失败的原因？
A: 三种方式：
1. 在执行日志详情中查看"步骤日志"表格
2. 使用"时间线"视图查看失败步骤的错误信息
3. 查看 `error` 字段的详细描述

### Q4: 重试机制何时生效？
A: 需要同时满足：
1. 步骤配置了 `max_retries > 0`
2. 错误类型匹配 `retry_on` 条件
3. 未超过最大重试次数

### Q5: 补偿是什么意思？
A: 当工作流执行失败且配置了补偿策略时：
- 系统会执行补偿步骤（通常是反向操作）
- 例如：创建订单失败后，补偿步骤会回滚库存
- 状态显示为"已补偿"

## 6. 技术限制

### 当前限制
- ❌ 设计器暂不支持条件分支的可视化编辑
- ❌ 设计器暂不支持循环步骤的可视化编辑
- ❌ 不支持子工作流嵌套
- ❌ 异步步骤的输出不能被后续步骤使用

### 浏览器要求
- Chrome 90+
- Firefox 88+
- Safari 14+
- Edge 90+

## 7. 快捷键

### 工作流设计器
- `Delete` - 删除选中的步骤
- `Ctrl/Cmd + S` - 保存工作流（开发中）
- `Ctrl/Cmd + Z` - 撤销（开发中）

### 执行日志
- `F5` - 刷新列表
- `Ctrl/Cmd + F` - 聚焦搜索框（开发中）
