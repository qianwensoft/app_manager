## 一、实现范围

**核心能力**: 同一台 Android 设备上运行的多个 form-app，可通过 AndroidBridge 本地中继互发事件。

**典型场景**: PDA 盘点 app 扫码后，触发入库 app 刷新列表；或仓库 app 提交后，通知主屏 app 播报语音。

**不依赖**: 
- ❌ 不需要服务端（离线可用）
- ❌ 不需要网络
- ❌ 不需要 STOMP（本地内存中继）

## 二、TypeScript 端实现 (`9be4739`)

### 新增文件

#### `form-app/src/runtime/crossDevice/types.ts`
```typescript
export interface CrossDeviceEvent {
  event: string                // 事件名
  payload: Record<string, any> // 自包含数据快照
  origin: { formCode, deviceId?, emittedAt, eventId }
  hop: number
}
```

#### `form-app/src/runtime/crossDevice/bridge.ts`
- `emitCrossApp()`: 构造 CrossDeviceEvent（含 origin/hop/eventId uuid），调 `AndroidBridge.emitCrossAppEvent(json)`
- `isCrossAppBridgeAvailable()`: 检查桥可用性
- `generateEventId()`: crypto.randomUUID() 或降级伪随机

#### `form-app/src/runtime/crossDevice/receiver.ts`
- `setupCrossDeviceReceiver()`: 注册 `window.dispatchCrossDeviceEvent`（供 Android 调用）
- **幂等去重**: EventIdCache LRU 256 条
- **防回环**: `origin.formCode === 当前 formCode` 则丢弃
- **hop 超限 warn**: `hop > 10` 仅 log 不丢弃（A2 决策：不做强限制）

#### `form-app/src/runtime/tools/emitCrossApp.ts`
- `emit_cross_app` 工具注册
- 参数: `target_form_code`, `event_name`, `data_src`
- 从 `ctx._crossDeviceHop` 读取 parentHop 传递

### 修改文件

- `EventEngineDeps` 加 `formAppCode?: string`
- `makeCtx()` 透传 `_crossDeviceHop`

object FormAppRegistry {

### 修改文件

**`FormAppBridge.kt`**:
- 构造器加 `formAppCode: String` 参数
- 新增 `@JavascriptInterface fun emitCrossAppEvent(jsonPayload: String)`:

  4. 补全 `origin.deviceId`（ANDROID_ID）
  5. `targetWebView.post { evaluateJavascript("window.dispatchCrossDeviceEvent(...)") }`
  6. 异常捕获 + Log

## 四、数据流（端到端）

### 发送端（form-app A）

1. **用户动作触发事件**（如按钮点击）
2. **事件动作链包含** `emit_cross_app`:
   ```json
   {
     "type": "emit_cross_app",
     "target_form_code": "app_b",
     "event_name": "ping",
     "data_src": "$form.message"
   }
   ```
3. **工具执行**: `emitCrossApp(currentFormCode='app_a', target={formCode:'app_b'}, event='ping', payload={message:'hello'}, parentHop=0)`
4. **构造信封**: `CrossDeviceEvent{ event:'ping', payload:{message:'hello'}, origin:{formCode:'app_a', eventId:uuid}, hop:1 }`
5. **调 Android 桥**: `AndroidBridge.emitCrossAppEvent(JSON.stringify({...envelope, _target:{formCode:'app_b'}}))`

### Android 中继层

6. **FormAppBridge.emitCrossAppEvent** 收到 JSON
7. 提取 `_target.formCode = 'app_b'`
8. `FormAppRegistry.find('app_b')` 查找目标 WebView
9. 移除 `_target`，补全 `origin.deviceId`
10. `targetWebView.post { evaluateJavascript("window.dispatchCrossDeviceEvent('...')") }`

### 接收端（form-app B）

11. **window.dispatchCrossDeviceEvent(json)** 被调用
12. **receiver.ts 处理**:
    - 幂等去重（eventId 在 LRU？丢弃 : 加入）
    - 防回环（origin.formCode === 'app_b'？丢弃）
    - hop 超限 warn（hop > 10 仅 log）
13. **回调上层**: `onReceive(event='ping', payload={message:'hello'}, hop=1)`
14. **setupAppEvents 注册的回调**: `eventManager.emit('ping', JSON.stringify({message:'hello', _hop:1}))`
15. **eventEngine custom_event 源**:
    - 解析 JSON，提取 `_hop=1`
    - 清理 `_hop`，构造 `EventContext{ event:{message:'hello'}, _crossDeviceHop:1 }`
16. **匹配监听 'ping' 的事件流**，执行动作链（如 `toast` 显示 `$event.message`）

## 七、已知限制与后续

### 已知限制
1. **多实例冲突**: 同一 formCode 同时打开两个 Activity，后者覆盖前者（`FormAppRegistry.register` 直接覆盖）。暂不支持一对多广播。
2. **无服务端审计**: 同设备内跨 app emit 不经服务端，无法审计/限流。
3. **线程安全**: `FormAppRegistry` 用 `ConcurrentHashMap`，`targetWebView.post{}` 确保 UI 线程，已兜底。

### 后续工作
- **第 7b 步**（跨设备 STOMP）:
  - 服务端 `POST /api/form-app/cross-event` 端点（权限校验 + 幂等 eventId + 补全 origin/hop）
  - form-app WebSocket 订阅 `/topic/form-app/<code>/events`
  - 复用 7a 的 TS 接收端（receiver.ts 同一套）
- **第 8 步**（yjs 协同）:
  - AppState 作 yjs 文档
  - STOMP 作 provider transport
  - 状态共享 ≠ 事件跨设备（A2 已明确）
