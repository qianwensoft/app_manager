## 更新概述

本次更新主要实现了**前台应用实时监控**功能，涵盖 Android 端检测、服务器端处理、前端实时显示的完整链路，并完善了出站连接器的前台应用过滤功能。

## 核心功能

### 1. 前台应用实时监控 🎯

**Android Agent 端**:
- ✨ 新增 `ForegroundAppMonitor` 实时监听器
  - 2 秒检测周期，CPU 占用 < 0.1%
  - 应用变化时立即上报，无需等待心跳
  - 自动生命周期管理（连接时启动，断开时停止）

- ✨ 新增 `ForegroundAppDetector` 检测工具
  - 支持 Android 5.0+ (API 21+)
  - 使用 `UsageStatsManager` 获取前台应用
  - 完善的权限检查和错误处理

- ✨ 权限引导优化
  - 橙色警告横幅提示授权
  - 一键跳转系统设置
  - 已授权时自动隐藏

**服务器端**:
- ✨ 心跳处理增强
  - 检测前台应用变化
  - 变化时通过 STOMP 实时推送到监控页面
  - 空值保护：心跳包未包含前台应用时不覆盖有效数据

- ✨ 应用名称映射
  - 自动匹配 APK 管理中的应用
  - 前台应用显示应用名称而非包名
  - 一次查询，O(1) 映射复杂度

**前端**:
- ✨ 实时监控页面
  - STOMP 订阅 `/topic/monitor/agent-connections`
  - Agent 上线/下线/前台应用变化自动更新
  - 显示格式：`Chrome 浏览器 / com.android.chrome`

**实时性能**:
```
用户切换应用 → < 2秒检测 → < 100ms上报 → < 50ms推送 → 前端自动更新
总延迟: < 2.5秒
```

### 2. 连接器前台应用过滤 🔧

**功能说明**:
- 出站连接器支持前台应用白名单过滤
- 只在配置的应用前台时触发连接器
- 实时读取设备最新的前台应用状态

**配置方式**:
```json
{
  "trigger_config_json": {
    "foreground_packages": [
      "com.android.chrome",
      "com.example.myapp"
    ]
  }
}
```

**使用场景**:
- 游戏内事件监控（只在游戏前台时触发）
- 特定应用协同（多个应用的任意一个前台时触发）
- 避免误触发（切换到其他应用时不触发）

## 技术改进

### 性能优化
1. **应用名称映射缓存**: 预加载所有 APK，避免 N+1 查询
2. **STOMP 推送优化**: 只在变化时推送，避免重复
3. **设备列表限制**: 最多推送 100 个在线设备

### 数据保护
1. **空值保护**: 心跳包未包含字段时保留原值
2. **变化检测**: 只在确实变化时才触发推送
3. **权限检查**: 未授权时跳过检测，不报错

### 代码质量
1. **详细日志**: 完整的调试信息，便于排查问题
2. **错误处理**: 健壮的异常捕获和降级处理
3. **生命周期管理**: 自动启动/停止，避免资源泄漏

## 使用指南

### 为设备启用前台应用监控

1. 在 Agent 设备上打开权限页面
2. 看到橙色警告横幅："需要授权使用情况访问权限"
3. 点击"立即授权"按钮
4. 在系统设置中找到 Agent 应用并授权
5. 返回 Agent，横幅自动消失
6. 前台应用开始实时上报

### 查看实时监控

1. 打开管理后台，进入"设置" → "运行监控"
2. 查看在线设备数量和列表
3. 查看每个设备的前台应用（自动显示应用名称）
4. 无需刷新，自动实时更新

### 配置连接器前台应用过滤

1. 进入"出站连接器"配置页面
2. 创建或编辑连接器
3. 在 `trigger_config_json` 中添加：
```json
{
  "foreground_packages": ["com.your.app", "com.another.app"]
}
```
4. 保存后，连接器只在这些应用前台时触发

### 设置 APK 应用名称

1. 进入"APK 管理"页面
2. 点击应用右侧的"编辑"按钮
3. 设置"应用名称"（如"微信"、"Chrome"）
4. 设置完成后，监控页面自动显示应用名称

## 已知问题

1. **数据过期**: 当 Agent 撤销使用情况访问权限后，前台应用保持最后一次的值（可能过时）
   - **解决方案**: 未来版本将添加数据时间戳和过期标记

2. **权限撤销检测**: Agent 端未主动检测权限撤销
   - **影响**: 权限撤销后监听器仍然运行（但检测失败）
   - **解决方案**: 未来版本添加权限变化监听
