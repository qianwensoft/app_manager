# 工单编号改造 + 搜索功能增强

## 改动时间
2026-06-22

## 改动内容

### 1. 工单编号规则改造

**新规则：** 工单类型编码 + 日期(YYMMDD) + 4位流水号

**示例：**
- 类型编码 `Y`，日期 2026年6月22日 → `Y2606220001`
- 类型编码为空时使用 `WO` 作为默认前缀 → `WO2606220001`

**实现逻辑：**
- 每天每种类型从 0001 开始计数
- 查询当天该类型已有的最大流水号，新工单流水号 = 最大流水号 + 1
- 数据库查询使用 `LIKE` 匹配前缀，按编号降序取第一条

**代码位置：**
- `server/api/work_order.go:33` - `genWorkOrderCode(typeCode string)` 函数

### 2. 工单列表/看板搜索功能增强

**新增参数：** `search_key`

**搜索范围（OR 查询）：**
1. 工单编号 (`code`)
2. 业务单号 (`business_no`)
3. 其他编码 (`other_codes`)
4. 标题 (`title`)
5. 描述 (`description`)

**后端实现：**
- `server/api/work_order.go:143` - 在 `ListWorkOrders` 函数中添加关键词搜索逻辑
- SQL: `WHERE code LIKE ? OR business_no LIKE ? OR other_codes LIKE ? OR title LIKE ? OR description LIKE ?`

**前端实现：**
- `web/src/views/work-orders/WorkOrders.vue`
  - 第17行：添加搜索输入框（宽度280px，占位符提示搜索范围）
  - 支持回车键搜索 + 清空按钮
  - 搜索条件同步到 URL 查询参数（支持浏览器前进/后退）
  - 列表视图和看板视图均支持搜索

## 注意事项

1. **流水号唯一性：** 理论上高并发场景下可能产生重复编号（两个请求同时查到相同的最大流水号），建议未来考虑：
   - 使用数据库自增序列
   - 或在 `code` 字段添加唯一索引，插入失败时重试

2. **搜索性能：** `LIKE '%keyword%'` 无法使用索引，大数据量时可能较慢，建议未来考虑：
   - 全文搜索引擎（如 Elasticsearch）
   - 或对搜索字段建立全文索引

3. **已有工单编号：** 此次改造仅影响新建工单，历史工单编号保持不变

## 测试建议

1. 创建不同类型的工单，验证编号格式正确
2. 同一类型连续创建多个工单，验证流水号递增
3. 跨天创建工单，验证流水号重置为 0001
4. 测试搜索功能，使用工单号、业务单号、标题等关键词搜索
5. 测试看板视图下的搜索功能
