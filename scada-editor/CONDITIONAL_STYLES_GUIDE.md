# 条件样式功能使用指南

## 概述

SCADA 编辑器现在支持基于表达式的条件样式规则，允许根据数据绑定值、扩展字段或其他组件的值动态设置元素的颜色。

## 功能特性

- ✅ 支持文本颜色、填充色、边框色的条件设置
- ✅ 支持复杂的 JavaScript 表达式
- ✅ 可访问绑定值、扩展数据、其他组件值
- ✅ 规则按顺序评估，第一个匹配的规则生效
- ✅ 支持引用全局参数、点位数据、时间函数等

## 使用方法

### 1. 打开条件样式配置

1. 在 SCADA 编辑器中选择一个元素（文本、按钮等）
2. 在右侧属性面板中找到「条件样式」区域
3. 展开该区域查看配置选项

### 2. 添加规则

每个样式属性（文本颜色、填充色、边框色）都可以配置多条规则：

1. 点击「+ 添加规则」按钮
2. 填写以下字段：
   - **规则名称**（可选）：如"高温告警"、"正常状态"等
   - **条件表达式**：JavaScript 表达式，返回 true 时应用该规则
   - **颜色**：满足条件时应用的颜色值

### 3. 表达式语法

条件表达式中可以使用以下变量：

#### 基础变量

- **`v`** - 当前元素绑定的数值
- **`text`** - 当前元素显示的文本值
- **`ext`** - 当前元素的扩展数据对象（如 `ext.max`, `ext.warning`）

#### 访问其他组件

- **`el(name, property)`** - 获取其他组件的属性值
  ```javascript
  el('温度传感器', 'text')           // 获取显示文本
  el('阈值配置', 'extData.max')      // 获取扩展数据
  ```

#### 全局参数与点位数据

- **`params`** - 全局参数对象
- **`P(key)`** - 获取全局参数值
- **`point`** - 点位数据对象
- **`V(path)`** - 获取点位数据（点分隔路径）

#### 时间函数

- `now()`, `nowMs()`, `today()`
- `formatDate()`, `addDays()`, `addHours()`
- 等（参考表达式文档）

#### 工具函数

- `num(v)` - 转换为数字
- `str(v)` - 转换为字符串
- `round(n, digits)` - 四舍五入
- `coalesce(...args)` - 返回第一个非空值

## 示例场景

### 场景 1: 基于绑定值的颜色告警

元素绑定温度数据，根据温度值设置不同颜色：

**规则 1（危险）：**
- 条件：`v > 80`
- 颜色：`#ff0000`（红色）

**规则 2（警告）：**
- 条件：`v > 60`
- 颜色：`#ff9800`（橙色）

**规则 3（正常）：**
- 条件：`v >= 0`
- 颜色：`#4caf50`（绿色）

### 场景 2: 基于扩展字段的阈值判定

在扩展数据中设置：
- `max`: `100`
- `warning`: `80`

条件表达式：

**规则 1：**
- 条件：`Number(text) > Number(ext.max)`
- 颜色：`#f44336`

**规则 2：**
- 条件：`Number(text) > Number(ext.warning)`
- 颜色：`#ff9800`

**规则 3：**
- 条件：`true`
- 颜色：`#4caf50`

### 场景 3: 引用其他组件的扩展数据

显示元素引用配置组件的阈值：

**配置组件**（名称：`阈值配置`）扩展数据：
- `max`: `100`
- `min`: `20`

**显示元素**条件表达式：

```javascript
Number(text) > Number(el('阈值配置', 'extData.max'))
```

### 场景 4: 复杂的逻辑判断

```javascript
// 同时满足多个条件
v > 50 && v < 100 && ext.enabled === 'true'

// 使用或逻辑
v < 10 || v > 90

// 使用工具函数
num(text) >= num(ext.min) && num(text) <= num(ext.max)

// 字符串比较
text === 'ALARM' || text === 'ERROR'

// 时间范围判断（配合日期绑定）
nowMs() - toTimestamp(v) < 60000  // 数据在 1 分钟内
```

### 场景 5: 使用全局参数

设置全局参数 `dangerThreshold: 80`

条件表达式：
```javascript
v > P('dangerThreshold')
```

## 最佳实践

### 1. 规则顺序

规则按顺序评估，**第一个匹配的规则生效**。因此：

✅ **正确**：从严格到宽松
```
规则 1: v > 80  → 红色
规则 2: v > 60  → 橙色
规则 3: v >= 0  → 绿色
```

❌ **错误**：宽松的规则在前会覆盖后面的
```
规则 1: v >= 0  → 绿色（所有正数都会匹配，后面的规则永远不会执行）
规则 2: v > 60  → 橙色
规则 3: v > 80  → 红色
```

### 2. 类型转换

扩展数据和文本值都是字符串，进行数值比较时需要转换：

✅ **正确**：
```javascript
Number(text) > Number(ext.max)
num(text) > num(ext.max)
```

❌ **错误**（字符串比较）：
```javascript
text > ext.max  // "9" > "100" 会返回 true！
```

### 3. 默认规则

建议最后添加一个兜底规则：

```javascript
true  // 始终匹配，用于设置默认颜色
```

### 4. 调试技巧

- 在规则名称中描述清楚条件（如"温度>80°C"）
- 使用控制台查看表达式返回值
- 从简单表达式开始，逐步增加复杂度

### 5. 性能考虑

- 条件样式在每次数据更新时计算
- 避免过于复杂的表达式
- 考虑使用扩展数据缓存计算结果

## 常见问题

### Q: 为什么我的规则不生效？

A: 检查以下几点：
1. 规则顺序是否正确（是否被前面的规则覆盖）
2. 表达式语法是否正确
3. 是否进行了必要的类型转换
4. 是否启用了实时数据（编辑器中需要开启"实时数据"）

### Q: 如何引用嵌套的扩展数据？

A: 使用点分隔语法：
```javascript
ext.config.max
el('组件名', 'extData.nested.value')
```

### Q: 表达式报错怎么办？

A: 表达式错误时规则会被跳过，不会应用任何颜色。检查：
1. 语法是否正确
2. 引用的变量是否存在
3. 是否忘记类型转换

### Q: 可以在条件中调用自定义函数吗？

A: 可以！在项目的全局参数/自定义函数中定义函数后，可以在条件表达式中直接调用。

## 技术实现

条件样式功能基于以下技术实现：

- **类型定义**：`ConditionalColorRule`, `ConditionalStyles` (`src/types/index.ts`)
- **解析引擎**：`src/runtime/conditionalStyles.ts`
- **表达式引擎**：`src/runtime/expression.ts`
- **UI 编辑器**：`ConditionalColorRulesEditor` (`src/components/PropertiesPanel.tsx`)
- **渲染集成**：`CanvasViewer.tsx`, `CanvasBoard.tsx`
